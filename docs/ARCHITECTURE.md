# 原理、数据流与实现位置

## 1. 两个算子为什么这样选

Add：`z[i] = x[i] + y[i]`。每个元素彼此独立，便于验证内存搬运、尾部和多核切分。在仅一次读 x/y、一次写 z 的理想模型下，N 个元素、每元素 d 字节，必要数据量约为 `3*N*d`。小输入可能受启动开销限制，大输入可能受带宽限制；这些是待用测量检验的假设。

Softmax：对每行 `m=max(x)`，`u[j]=exp(x[j]-m)`，`s=sum(u)`，`y[j]=u[j]/s`。减去同一个最大值不改变数学结果，并使指数自变量不大于零。有限输入下每行输出非负、行和约为 1。行之间独立，行内存在归约依赖，因此适合学习与 Add 不同的并行划分。

## 2. Host 与 Device 的职责

```text
调用方输入、shape、dtype
          ↓
Host 注册 / 参数检查 / 输出推导
          ↓
Tiling：选择 block 数、分块长度、尾部策略和本地空间
          ↓  序列化元数据
Device Kernel：按核索引定位 GM 区间
          ↓
GM → Local Memory → 向量计算/归约 → GM
          ↓
同步完成 → 正确性比较 → 性能记录
```

`op_host/<op>.cpp` 负责注册与输入契约，`op_host/tiling.cpp` 负责策略，`op_host/<op>_tiling.h` 负责元数据契约，`op_kernel/<op>.cpp` 负责设备计算。初始化时这些文件故意用 `#error` 阻断误编译；它们是任务位置，不是可运行 Ascend C 实现。

## 3. 核间与核内是两层切分

先把 N 个工作项分给 C 个核：`q,r=divmod(N,C)`；前 r 个核各拿 q+1，其余各拿 q。第 c 核起点为 `c*q+min(c,r)`。再把每核区间按 tile 长度切成若干段。

本机练习把“工作项”视作 Add 元素或 Softmax 整行。真实设备需要进一步处理搬运对齐、向量掩码、有效长度、核数上限与 Local Memory 预算。数学区间划分通过，不能证明设备的字节对齐或指令长度合法。

核心不变量：每个有效元素只被一个核写入；块内读写不越过有效区间；最后一个 tile 的有效长度可能小于容量。输入太小应考虑减少核数；本机练习允许空闲核以验证划分，实际启动策略另行决定。

## 4. 内存与流水线

Add 若 x/y/z 各一组缓冲，tile 容量 T、dtype 大小 d、缓冲份数 B，简化预算为 `3*T*d*B`，还需加上对齐、临时区和保留空间。Softmax 的输入/输出、中间 FP32 值、归约 scratch 也必须逐项计算。具体空间归属、容量和 API 约束以目标芯片和对应 CANN 为准。

单缓冲基线先完成 CopyIn→Compute→CopyOut。双缓冲的目标是让不同块的搬运与计算重叠，但多占空间且需要正确队列/事件管理。缓冲份数为 2 不自动等于更快；用 profiler 确认重叠和瓶颈。

尾部不能通过越界读取再丢弃结果来处理。确认对应版本支持的搬运/填充/掩码方式，区分有效元素数与对齐分配长度。Softmax max 归约的填充元素通常需不影响最大值，sum 阶段也需避免无效元素参与；按所用实现明确规则。

## 5. 长行的边界

初版 Softmax 只支持能容纳整行与所需临时区的列宽。按行切分可安全并行；把一行分成多段各自 Softmax 再拼接会算错，因为各段分母不同。长行扩展需要跨块 max/sum、多遍或其他经过证明的算法，作为后续研究，不直接复用 Add 分块策略。
