# 算子契约、测试与题目验收

## 1. 初版支持边界

| 项目 | Add | 行级 Softmax |
|---|---|---|
| 数学含义 | 同形状逐元素相加，无广播 | 二维 `[rows,cols]`，仅末轴 |
| 布局 | 连续 ND，展平后计算 | 连续 ND |
| 目标类型 | 先 FP32，后 FP16 | 先 FP32，后 FP16；中间归约精度另行验证 |
| 空输入 | 本机返回空列表；设备 Host 零元素早返回，不启动核 | 本机空 batch 返回空；零列/非矩形报错；设备按契约实现 |
| 数值范围 | 初版要求有限输入，测试避免输出溢出 | 初版要求有限输入，不定义 NaN/Inf 传播 |
| 超资源输入 | 按合法 tile 切分 | 初版拒绝超过已验证行宽的输入 |

Python 参考用 double 精度语义建立数学基准，不执行 FP16/FP32 硬件舍入。设备测试应先按目标 dtype 量化输入，再转高精度算参考，最后按约定比较。不要拿不同数值的输入做精度对比。

## 2. 正确性矩阵

`configs/cases.json` 是初始候选矩阵，超出设备支持上限的 case 标记为拒绝或尚未支持，不能跳过后宣称全部支持。

- Add：N=0、1、17、31、32、33、257、1024、65537、1048576；覆盖尾部、核数不整除、大小规模。
- Softmax：`[1,1]`、`[2,3]`、`[3,17]`、`[8,33]`、`[32,128]`、`[4,1024]`、`[128,1024]`。
- 数据：全零、等值、正负混合、固定种子随机、稳定范围内大幅值；Softmax 包含 `[1000,1001,1002]`。
- 负例：不匹配 shape、零列、非连续/不支持 dtype、非有限数值、超支持行宽。明确是调用层检查还是 kernel 支持。
- 并行配置：单核与多核、tile 不整除、单/双缓冲。每次策略变更重跑边界集。

比较定义：每元素满足 `abs(actual-ref) <= atol + rtol*abs(ref)`，另记录 max_abs_error、有效相对误差和失败索引。FP32 初始试用 `atol=1e-6, rtol=1e-5`；FP16 初始试用 `atol=1e-3, rtol=1e-2`。这是设计起点，必须结合输出规模、指数实现和 dtype 范围审定，不能为掩盖错误随意放宽。Softmax 独立检查非负性、有限性及行和误差，行和阈值另记录。

## 3. 题目最低要求如何证明

| 题目要求 | 计划证据 | 当前状态 |
|---|---|---|
| 不少于 2 个典型算子 | Add、Softmax 的源码、构建产物、正确性日志 | 仅骨架，未完成 |
| Host 注册 | Host schema + 部署记录 + 一次真实调用 | 待设备 |
| Kernel | 设备入口源码与真实执行日志 | 待设备 |
| Tiling | 策略源码、元数据与形状边界测试 | 仅本机数学练习可用 |
| 内存搬运 | 真实 CopyIn/CopyOut、尾部检查与内存验证 | 待设备 |
| 向量化 | 对应 API 与精度/执行证据 | 待设备 |
| 多核并行 | 分核源码、配置和单/多核对照 | 仅本机切分练习可用 |
| 性能对比 | 两算子在同设备、同输入、同计时范围下对基础/内置实现 | 未测 |
| 至少一项优化 | 固定基线、单变量消融、适用范围和重复测量 | 待实验 |

至少四项技术环节形成证据才可勾选最低环节要求；本项目目标六项全部覆盖。独立的 Python 数学测试不会计入已完成的设备环节。
