# 学习计划：先本机，后设备

默认每周 6–8 小时：两次 90 分钟实现、一次 90 分钟资料阅读和画图、一次 90–180 分钟测试与复盘。时间不足就延长周数，不跳过阶段验收。设备阶段从实际拿到可用服务器那周开始，不把租卡或设备到位当成已经完成。

## 1. 每次学习的固定方法

1. 先预测：手算一个输入，预测输出、每核区间或内存需求。
2. 再实现：只编辑 `problem/`；卡住先读提示，之后才看同目录 `solution/`。
3. 做实验：运行该阶段测试，主动新增一个边界案例。
4. 最后解释：写清“输入如何被拆分、谁负责哪块数据、如何保证无越界、证据说明了什么”。

看过答案后关掉答案，在 2 天和 7 天后各重写一次关键函数。每周复制 `reports/WEEKLY_TEMPLATE.md` 写一页记录；通过答案测试只说明参考实现可用。

## 2. 本机四周

| 周 | 学什么、为什么 | 本周动手 | 完成标准 |
|---|---|---|---|
| 1 | 数组/shape、数值稳定性、C++ 指针与内存；先知道算子必须算出什么 | 第 01 组练习；C++ 连续数组 Add；解释减 max 的 Softmax | `test 01` 通过，能解释大幅值和非法输入 |
| 2 | GM/Local Memory 概念、元素数与字节数、核间切分和核内 tile | 第 02 组练习；手画 17 个元素的分块；估算缓冲区 | `test 02` 通过，所有元素恰好覆盖一次 |
| 3 | 搬入→计算→搬出、行级归约依赖、缓冲区生命周期 | 第 03 组练习；运行整体 demo；解释为何 Python 顺序模拟没有重叠执行 | `test all` 与 `demo` 通过，补一项边界测试 |
| 4 | Host/Kernel 分工、注册链路、版本匹配、实验设计 | 对照官方样例标注各文件职责，完成支持矩阵与性能实验草案 | 能手写流程图，TODO 的 D/A/S/R 阶段都有输入与验收理解 |

本机 C++ 热身可使用已有编译器执行 `c++ -std=c++17 -Wall -Wextra -Werror work/cpp-warmup.cpp -o work/cpp-warmup`，再运行程序。它验证语言基础，不编译 Ascend C。若本机没有编译器，这一项单独标为待安装工具链，其余 Python 练习可继续。

四周后应能解释：Host 为何计算 Tiling；block 数与数据规模为何相关；UB 容量为何限制 tile；尾部为什么不能直接按完整 tile 读取；Softmax 为什么需要整行统计量。

## 3. 有设备后四周

| 周 | 首要目标 | 当周禁止跳过的检查 | 产物 |
|---|---|---|---|
| 1 | 固定环境、复现对应版本官方 Add、打通注册与调用 | 实际芯片、驱动/固件/CANN 匹配；日志能定位编译或运行失败 | 环境记录、官方样例日志、真实构建入口 |
| 2 | 自己实现 Add，从单核到多核，从整块到尾部 | 先正确再性能；每个 dtype 独立测；Host 拒绝不支持输入 | Add 代码、精度报告、首轮 tile/core 扫描 |
| 3 | 自己实现有行宽上限的行级 Softmax | 大幅值稳定性、FP16 中间精度、尾行/尾列、UB/scratch 预算 | Softmax 代码、边界日志、行宽/核数分析 |
| 4 | 固定版本做对比和消融，整理复现材料 | 相同 dtype/shape/计时范围；同步等待；保留变慢案例 | 两个算子性能对比、至少一项优化成果、报告 |

## 4. 控制课题范围

必做：连续 ND 数据；Add 同形状、不广播；Softmax 二维、末轴、有限数值、行宽在单核本地存储可容纳范围内。优先 FP32 正确性，再拓展 FP16。超过支持范围明确报错；不能静默算错。

主优化路线：Add 的 tile 大小/核数/双缓冲；Softmax 的按行分配、行复用和中间计算组织。一次只改一个因素。暂不引入 Matmul、FlashAttention、完整推理框架改造或自动调优器，以免两算子的闭环没有完成。

若设备仍未到位，完成 M3 后可以继续用 C++ 重写分块与数学基准、补边界测试、整理实验方案；设备阶段保持待办。无设备不能完成该题的最终性能验收。
